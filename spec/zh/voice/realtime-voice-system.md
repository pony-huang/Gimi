## 一分钟总览

实时语音默认是**客户端 VAD 分轮，而非服务端全双工**；每轮都新建一条后端连接。级联链路如下：

```text
麦克风
   │  回声消除（硬件优先，软件兜底，两者互斥）
   v
VAD 逐帧给出语音概率
   │  切句：起止阈值、前置缓冲、单句上限（数值见链路文档）
   v
整段话语 PCM ─> 识别 ─> 最终文字（中间结果只用于显示）
   │
   ├─ Chatbot：级联语音模型，保存会话历史，无工具
   v
逐句 TTS（会话式优先，一次性兜底）
   v
PCM 播放
   ^── 用户开口 ─> 立刻停播，取消在途生成与合成
```

三个必须记住的后果：
- **打断成本低、语义清晰**。人声一起就取消整条付费链路（LLM + TTS），不等服务端判轮结束。
- **没有跨轮连接复用**。每轮重新握手、重发上下文，长通话的延迟与费用未经优化。
- **单句有硬上限**。超长独白被强制切成多轮，而不是报错。

原生实时是刻意的例外：常驻全双工会话、上行持续推流、由服务端 VAD 判定轮次边界。它复用采集／回声消除／播放外壳，但绕过整条级联链路。见[对话方式与语音链路](#对话方式与语音链路)和[供应商与能力矩阵](#供应商与能力矩阵)。

## 分层与所有权

| 模块 | 负责 | 不负责 |
|---|---|---|
| `domain:voice` | 会话契约、状态快照、失败分类、能力解析与会话式合成接口 | 任何 Android / ADK / Compose 类型 |
| `core:audio` | 录音、VAD、软 AEC、播放参考缓冲、音频格式契约 | 业务语义 |
| `data:voice` | 会话装配、AEC/VAD 编排、播放、设备路由、能力注册表、前台服务、进程级控制器 | 模型选择、Agent 执行、厂商适配器 |
| `:data:modelaccess` | 厂商模型／语音适配器（实时、级联、ASR/TTS 协议与探针）、工厂装配 | 设备、AEC、播放、会话所有权 |
| `data:agent`/`voice` | 语音会话运行时、双工会话门面、实时工具桥；把聊天模式接上完整 Agent | 厂商模型适配器（已迁至 `:data:modelaccess`） |
| `feature:chat`/`realtime` | 界面状态映射、转发用户意图 | 会话所有权、生命周期结束 |
| `:app` | 清单、权限、通知权限引导、导航回跳 | — |

所有权约定：
- 会话由**进程级通话控制器**持有；离开页面、进入后台、销毁 Chat 页面都不得关闭它。
- 只有用户显式结束通话才释放资源——从语音页或状态栏通知。
- 录音权限由界面入口取得，会话层只负责在拿不到麦克风时归类为 `Microphone` 失败。

## 对话方式与语音链路

三条链路统一使用 Chatbot。文字模式与语音绑定同一个 Chatbot 会话；启动或切换通话只接受 Chatbot。

| 链路 | 模型职责 | 可用条件 |
|---|---|---|
| 级联 | 识别 → Chatbot 对话模型 → 合成 | 识别与合成模型有效 |
| 半级联 | Chatbot 模型直接理解音频，合成模型播报回复 | 全模态 Chatbot 模型且合成模型有效 |
| 原生实时 | 厂商全双工 Realtime 模型处理双向音频 | 有效 Realtime 模型且已注册双工适配器 |

级联与半级联恢复绑定的会话，保存用户输入和完整播出的回复。原生实时只保存定稿转写，建立连接时不重放历史。
**配置继承。** 全局默认提供所有字段；单条对话可以逐字段覆盖，未覆盖字段继承默认。当某条链路需要的模型还缺着时，保留已保存的配置不动，等完整配置到齐再原子提交。放弃一次未填完的编辑，只丢弃那些没补齐的选择。

### Chatbot 角色与会话切换

角色来自共享目录，文字与语音读取同一份按会话的选择。换角色保留历史，从后续回复起生效。原生实时把指令更新推到已有连接上，不动音频配置、音色和工具；文字与级联链路则走各自的常规指令／话轮流程。实时聊天从 Chatbot 输入框里麦克风旁的入口进入，文字聊天保留自己的听写入口。当前会话已为空且空闲时再请求新建会话，只提示并保留该会话。

### 实时助手工具

后端保留一条客户端执行的工具桥；应用的通话控制器只启动 Chatbot 通话，而 Chatbot 通话没有助手工具。以下规则约束这条保留的路径：
- **白名单，而非自动发现。** 工具桥复用聊天 Agent 的贡献来源，但只跑一份显式白名单（local、mcp、plugin、appfunction、sandbox）。刻意排除：依赖 ADK Runner 的来源（会话状态、工件、用户输入挂起、技能）、厂商声明／厂商侧执行且本地运行会抛错的来源、以及通话中毫无意义的模型目录工具。新增来源只能经过一次有意识的白名单决策才能加入。
- **没有 Runner，也没有持久化会话。** 执行跑在裸上下文上；语音通话全部自动批准确认，与语音 Chat 模式同一策略。
- **声明按通话解析一次，且跨重连存活。** 坏掉的 MCP server 最多把探测预算加到通话启动上；重连即新会话，所以声明会自动重新下发（线上形状见链路文档）。
- **轮次流程。** 参数流入时先缓存工具调用，收到完成事件再定稿，响应结束时冲出未定稿的调用。遇到明确的非完成状态和打断时，丢弃被截断的参数——绝不执行、也不写回。轮次在接收循环之外串行执行；结果逐个写回，每轮触发一次响应。参数永不播报；断线取消在途轮次。
- **界面反馈。** 工具轮未产出时，通话保持在思考状态，让第二轮的转写继续拼接；"正在调用工具"提示在第二轮首个输出、打断、重连或下一轮用户发言时清除。

### 默认 Realtime 选择

Realtime 模型可设为全局默认，也可在对话待机时单独覆盖。记住这几个坑：

| 事实 | 规则 |
|---|---|
| 候选范围 | 只列出「已启用 + 已配密钥 + 声明了原生适配器」的服务；带 Realtime 标记却没有适配器的模型会静默回落级联，所以整组**隐藏，而非显示为不可选**。 |
| 音色表 | **不建音色表。** 每个适配器按模型声明一个缺省音色，并说明是否接受自由文本覆盖（一家接受声音复刻 id，另一家只给固定下拉）。 |
| 音色归属 | 对话内选择的音色保存到该对话；清除覆盖后，只有链路和完整模型都匹配时才回退到记忆音色，否则用厂商默认。 |
| 可用性 | 服务、密钥、模型或适配器被删除／失效时，该选择算作缺失。 |
| 生效范围 | 配置快照在**通话开始时固定**；设置只在通话彻底结束后重新开放。 |

### 配置切换

配置在通话期间锁定。唯一值得知道的坑：若切换在当前话轮冲刷完之后失败，**原会话会被保留**，以便重试尚未提交的轮次——切换失败时绝不拆掉它。

## 供应商与能力矩阵

**STT 与 ASR 是两个能力位，不是同一件事的两种叫法。** STT 是专用的整段转写服务，ASR 是复用对话模型做识别。模型两者兼备时优先走专用 STT（更准、链路更短）。

| 服务 | 识别 | 流式识别 | 合成 | 会话式合成 | 音色 | 探测 |
|---|---|---|---|---|---|---|
| qwen-audio | 专用 STT | 有 | 有 | 无 | 按模型查表／缺省音色 + 自由文本覆盖 | 实时 WS 握手 |
| minimax-speech | STT（multipart） | 无 | SSE | 双向 WS | 远程 + 本地兜底 | 未注册 |
| mimo-speech | STT + ASR | 无 | 有 | 无 | 静态表 | 模型列表端点 |
| openai-speech | 专用 STT | 无 | 有（二进制 PCM） | 无 | 静态表／内置音色，不接受自定义 | 实时 WS 握手 |
| 聊天服务 | STT + ASR | 无 | 有 | 无 | 空 | 聊天服务探测 |

DashScope 级联不做会话式合成有明确理由：厂商按连接计费，长连接复用没有收益。**实时模型与级联模型共处同厂商的一条配置**——没有独立的 Realtime 服务种类；模型挂在厂商语音服务下，并带标记使级联选择器永远不会拾取。会话仍是常驻全双工：服务端 VAD 管判轮，模型原生听、原生说。原生路径里不易察觉的事实（接缝本身看代码即可）：
- **上行采样率按厂商不同。** 一家重采样到模型原生速率，另一家直接按采集速率喂入。遵循适配器声明的上行契约，别在工厂里写死速率。
- **打断语义按厂商不同。** 一家靠服务端自动取消再加一个截断补充，另一家完全靠服务端自动取消、并在静默窗口里丢弃残余音频。对自动取消的厂商不要发送截断／取消事件。
- **播放采用混合门控**——助手说话期间用本地 VAD 门控上行，残留回声才不会伪造出服务端打断。这就是全双工模式下采集仍要保留自己 VAD 的原因。
- **握手失败的分类是注入的**，因为传输内核只认 HTTP 状态码，不懂领域含义。

### 能力解析

| 规则 | 行为 |
|---|---|
| 匹配键 | 合成只按服务 id 匹配；识别必须服务 id 与能力同时命中。 |
| 流式条目缺失 | 返回 null → 调用方退化为一次性识别。是软失败，不是异常。 |
| 语言模型能力 | 唯一恒为 true 的条目；这一层不判断模型是否可用。其余「声明了但未注册」的组合一律显式失败——别从它的宽松推断 STT/TTS/ASR 也会宽容。 |

### 失败分类

失败是一套**可翻译**的分类——界面只显示映射后的文案，绝不显示底层异常。

| 分类 | 来源 |
|---|---|
| Configuration | 默认缺失、可用性断言失败 |
| Audio processing | VAD / AEC 构造阶段 |
| Microphone | 音频焦点未授予、录音启动失败、录音回调报错 |
| Recognition | 识别流异常（且代次仍有效） |
| Generation | 生成流异常且没有更具体的分类 |
| Synthesis | 一次性 TTS 的非取消异常 |
| Playback | 播放失败 |
| Persistence | 进入 Chat 模式时目标会话已不存在；提交阶段 close 抛错。播放回执为空实现，所以「保存失败」这条主路径并不存在。 |
| Conversation busy | Agent 运行时门控拒绝了并发会话 |

另有一套**不映射到它的**低层分类，只用于设置页和连通性测试，通话界面看不到。两者别混。

## 通话中的手动输入

通话期间聊天与静音照常可用，手动文字／附件走原有链路提交；准备完成后才打断播放，提交失败保留草稿供重试。OpenAI 原生实时把文字与图片放进同一个用户事件、再显式触发回答；其他原生厂商没有手动消息入口，并明确拒绝文档和音频文件，手动消息也不跨重连缓存。

## 已知缺口

以下是当前代码的真实状态，不是待办建议。改这块之前请先确认它们是否已经修掉。
1. **保留的助手后端播放回执仍为空实现。** 持久化依赖 Runner，所以播放／结束／重试回执在该模式什么都不做。Chatbot 模式在生成前保存用户输入、话轮结束时保存播完的句子，挂断时保存当前回复已生成的文字。它恢复当前会话并持有运行时租约，重试沿用稳定事件 ID。原生实时 Chatbot 把定稿转写保存到绑定的会话。
2. **保留的助手后端会保存完整回复。** Runner 存的是完整事件，被打断的回答重开聊天时会照原样出现。用户在 Chatbot 模式中打断回复并继续通话时，只有播完的句子进入上下文。
3. **默认实时仓储没有单元测试。** 播放期回声决策本身已抽出并测试，但仓储内部的接线（playing／尾音风险判定、参考电平传递、上行 channel 竞态）没有测试缝；录音器、软消回音器、JNI 层和音轨只能真机验证。
4. **原生 Live 供应商只有两家。** 两家的厂商自有端点都已落地；原生接缝真实存在，但实现者只有级联适配器和两个 Realtime 适配器。文本模型实现该接口依旧不会自动获得实时语音能力。
5. **MiniMax 没有注册连通性探测**，其设置页「连接测试」行为未确认。
6. **没有独立的停止播报控件。** 开口或成功提交手动消息会打断当前回答。
7. **Chatbot 每轮重建连接并重发大量轮次的上下文**，长通话的延迟与费用未经优化。
8. **Realtime 需要有效的模型选择。** 每条对话可继承全局选择，也可在待机时单独指定；音色选择保存到该对话。
9. **工具轮与打断天然存在竞态。** 用户在工具执行中开口时，执行轮仍会写回结果并触发响应，服务端可能在用户说话中途播报回复。仓储侧的本地 VAD 会立即停播并清掉工具提示，最坏只是「回答来晚了」，不会卡状态。这一点只能真机验证。

## 改动这个系统时的检查清单

- **加供应商**——漏任何一项都会在设置页或运行期出问题：实现并注册识别／合成适配器，声明服务 id 与能力；注册每个 `(服务 id, 能力)` 组合（流式识别需要显式条目，否则静默退化为一次性）；注册服务音色表（缓存键含模型 id）并提供本地兜底；实现并注册连通性探测，否则「连接测试」行为未定义（MiniMax 现状）；端点与鉴权留在 data 层（厂商自有常量写死，只有代理型服务接受用户配置基址）；所有厂商选择走同一个模型工厂，未知厂商回落级联；补契约测试，限时跑在真实调度器而非虚拟时间上。
- **加原生 Realtime 供应商**（全双工，在上述清单之上）：打开一条常驻会话并等配置确认后才放行上行，确认前绝不推音频；在厂商语音服务下加实时模型分组（带实时标记、不带级联标记）并注册握手探测，端点保持厂商自有；**声明适配器能力**（服务 id、上行契约、按模型的缺省音色、内置音色、自定义音色策略），否则模型不会出现在候选里；走双工后端（重连退避与「重连即新会话」由门面持有，仓储只消费领域事件并喂入帧）；遵守上行门控——非播放期持续全量，播放期本地 VAD 门控（预滚与阈值见链路文档）；在上适配器而非工厂里声明按厂商的上行契约（采样率与线上形状见链路文档）；匹配厂商的打断语义（对自动取消的厂商不发截断／取消事件，只在需要处补截断）。
- **改工具面**——只改来源白名单；依赖 Runner 的能力（会话状态、工件、用户输入挂起、技能）必须留在外面，新增来源只能靠有意识决策加入。线上形状与执行语义测试见链路／测试文档。
- **改 VAD 阈值**——VAD 测试会挡；确认单句上限仍生效，否则长独白会一路占内存。
- **改播放格式**——输出必须保持 24 kHz 单声道 PCM16；在适配器里转换，或同时改播放器与 AEC 参考几何（见链路文档）。
- **改路由、AEC 收敛或播放期门控**——收敛窗口在**下一次播放开始**才起算，同一回复的后续句子不重开。播放期与声学尾音期用「实测回声基线 + 播放参考电平」把回声帧的 VAD 概率压到 0。撤防开关必须是播放器的 playing 状态（参考电平会虚假归零），播放结束后的尾音期不能立刻撤防。上行门控须同时看 playing 状态与尾音风险，绝不能看双工会话是否存在。改动前先跑回声门控测试（含「窗口内开始播放」「播完后混响尾音」「参考电平掉零」三组最小对照）。
- **改会话状态**——任何新的异步结果都要加代次守卫，否则取消后迟到的结果会漏进新一轮。
- **改领域接口或绑定**——必须装配并安装完整 APK，保留用户数据重启进程再验证；只装配不安装、或在旧 APK 上打热修，都可能让运行时混入不兼容类型。
- **验证真机行为**——认证、播放、路由只能真机确认，接口一致性不代表平台支持。
