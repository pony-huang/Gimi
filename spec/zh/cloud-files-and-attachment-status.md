# 云文件与附件独立状态卡设计需求

更新日期：2026-10-22。当前状态：按用户要求，所有 OpenAI Chat Completions 服务默认支持 PDF 上传与文件 ID 引用适配，不设厂商、模型或端点白名单；保持上传开关默认关闭。已接入请求转换、ADK 历史引用恢复、本地原文件保留与缺失恢复。真实厂商支持范围仍未在线验证，服务拒绝以实际错误反馈。

本文是本轮需求的统一依据。第 11—14 节保留此前实现检查点记录，当前行为以第 15 节及本页开头状态为准。上一轮已实现的 API 接入改版见 [API 接入设计基线](api-access-design.md)。图片、原型源码及渲染工具汇总在本地评审包 `temp/design-review/`；该目录按仓库要求不纳入 Git。

## 1. 目标与范围

在模型服务的扩展能力中增加文件上传。开启后，在发送附件时调用厂商官方上传 API，取得文件 ID，再按当前聊天接口支持的形式引用到请求中；用户不需要复制或填写文件 ID。

首期范围：

- 按用户最新要求，使用 OpenAI Chat Completions 协议的服务默认具备文件引用适配能力，不按厂商、模型或端点白名单拦截。厂商是否实际实现上传和文件读取由其响应决定；Claude／Anthropic 协议不纳入本期。
- 使用 SDK 调用接口，默认聊天协议保持 **Chat Completions**；不因使用 SDK 或开启上传而自动切换 Responses。
- 文件格式以 OpenAI 当前聊天接口和所选模型实际支持的文件输入为准。能上传到 Files API 不等于能作为聊天输入。
- 开启时，附件统一经过文件上传与引用能力校验；不支持文件引用的类型明确提示，不静默切回旧方式。
- 关闭时，保持原有附件发送逻辑；附件卡片在输入框外的布局仍沿用本次设计。
- 提供本应用上传记录的跨会话选择。首期不拉取其他客户端上传的账号文件，不建设知识库、向量检索或独立文件管理中心。

## 2. 已确认的设计规则

| 项目 | 最终要求 |
| --- | --- |
| 卡片粒度 | **每个文件一张独立状态卡**，不按整条消息或整组图片合成一张附件状态卡 |
| 图片 | 在该文件自己的卡片内显示缩略图，点击可放大；图片和文档保持相同卡片结构 |
| 其他文件 | 显示文件类型图标、名称、大小和自己的状态 |
| 上传操作 | 每个文件分别展示进度、失败原因、重试或取消；重试一个文件不影响其他文件 |
| 输入区 | 文件卡片和请求状态卡均放在文本输入框外；输入框不承载错误文案、上传进度或文件列表 |
| 默认方式 | 原有附件发送也采用逐文件卡片；普通聊天请求失败采用输入区上方的独立请求状态卡 |
| 草稿隔离 | 重试原失败任务，不覆盖、拼入或发送正在编辑的新草稿 |
| 云文件有效期 | 上传时设置，默认 7 天；设计选项为 1 天、7 天、30 天，仅影响后续新上传 |
| 发送时机 | 全部必要附件准备就绪后再请求模型；不能带着未成功的文件悄悄发送 |

普通聊天的“回复中断”属于请求级状态，不能伪装成某一个文件的上传失败。文件失败展示在对应文件卡内。当前失败不应同时在聊天记录和独立状态卡中重复提示；历史错误数据的持久化不因布局修改而直接删除。

## 3. 页面与交互

### 3.1 服务详情中的文件与工具设置

- 文件与厂商工具卡直接显示在服务详情的模型区下方，不再使用独立扩展能力页面。
- “云文件上传”开关默认关闭，与“厂商工具”独立，不互相控制；仅当前协议为 OpenAI Chat Completions 时显示文件卡，兼容厂商同样适用。
- 切换到其他协议时隐藏整张文件卡和说明，即便已有开启偏好；保留偏好，不影响其他协议原有发送方式。
- 开启后展示有效期选择，默认选中 7 天。
- 说明发送附件时自动上传、可跨会话再次选择、到期后失效。
- 设置遵循现有编辑草稿、保存及放弃修改机制，不在切换开关时立即写入生产配置。
- 调整有效期不追溯修改已经上传文件的期限；重新上传按当次设置重新计时。

### 3.2 聊天「＋」底部抽屉

- 保留拍照、照片、文件等入口，在附件区域新增“云文件”入口。
- 副标题为“选择已上传文件，在当前聊天中使用”。
- 当前服务未开启上传时隐藏云文件入口，不改变本地文件入口。
- 点击后在同一个抽屉内切换到云文件页，返回回到抽屉首页，不叠加第二层抽屉。

### 3.3 云文件选择页

- 顶部显示“云文件”和当前服务，列表限定当前服务与凭据作用域。
- 支持按文件名搜索、清空搜索、多选；选中项在筛选后仍应保留。
- 列表行显示文件名、类型、大小、剩余有效期或不可用原因。
- 底部固定“添加到聊天（数量）”；未选择时禁用。
- 确认后关闭抽屉，将选择项添加为当前草稿的独立文件卡片，不立即发送。
- 返回不提交本次选择，不能改变已有草稿附件。
- 同一文件不重复添加到同一份草稿；移除卡片只取消本次引用，不删除共享云文件。

### 3.4 文本输入框外的文件卡片

每张卡结构保持一致：左侧为缩略图或文件类型图标，中部为文件名、大小与状态，右侧为当前文件的操作。上传中可在该卡底部展示进度条。

- 文件卡按添加顺序排列，较多时在附件区域内滚动，不能使文本输入框消失。
- 普通文件和图片使用同样的间距、圆角、主题色与状态位置。
- 图片缩略图只关联当前文件，点击打开该图预览；关闭后回到原场景。
- 一个文件失败时，其他文件仍展示各自已就绪或进行中的状态。
- 普通模型请求失败时，使用另外的请求状态卡承载“回复中断／重试”，不把所有图片塞进该请求状态卡。

### 3.5 发送、重试与取消

1. 点击发送时固定本次文字和附件快照，校验服务、模型、格式与大小。
2. 对有效云端引用直接复用；需要上传的文件逐项进入上传状态。
3. 失败文件在自己的卡片内提示；重试仅恢复该文件，其他已就绪文件不重传。
4. 全部必要文件就绪后，使用原发送快照继续请求模型，不把后来编辑的新草稿带进去。
5. 单文件取消只影响该文件，本批次等待用户重新上传或移除该文件，不能自动忽略附件继续请求模型。
6. 模型调用失败后按原请求重试，避免重复写入用户消息；上传成功的引用继续复用。

## 4. 状态定义

### 4.1 每个附件的独立状态

| 状态 | 卡片呈现 | 可用操作与后续 |
| --- | --- | --- |
| 待发送 | 名称、大小、缩略图／图标 | 移除；发送时准备 |
| 有效云文件 | 剩余有效期 | 复用，无需重复上传；可移除本次引用 |
| 已过期、本地仍在 | “发送时重新上传” | 可选入草稿；发送时重传 |
| 正在上传 | 当前文件进度 | 取消当前文件 |
| 已就绪 | 当前文件就绪标记 | 等待其他文件，或继续模型请求 |
| 上传失败 | 当前文件失败原因 | 重试当前文件；不影响其他文件 |
| 已取消 | 当前文件已取消 | 重新上传或移除本次引用 |
| 源文件缺失 | 明确缺失提示 | 重新选择文件；不能假装上传成功 |
| 类型／模型不支持 | 解释不支持的原因 | 阻止本次发送，不静默改用其他协议 |

### 4.2 云文件列表与请求状态

| 场景 | 行为 |
| --- | --- |
| 还没有云文件 | 解释从本地选择附件并发送后，上传记录可供后续会话使用 |
| 搜索无结果 | 提供清空搜索操作，不丢失原有选中项 |
| 列表中已过期且本地缺失 | 禁止选中，说明需要重新选择源文件 |
| 普通聊天请求中断 | 输入框上方独立请求状态卡；保留已有回复及新草稿 |
| 重试普通聊天 | 重试上次请求，保留新草稿；可取消 |

## 5. 跨会话复用与到期

- 云文件记录跨会话共享，但按服务、实际端点和凭据作用域隔离。不同会话选择同一有效文件可复用 ID。
- 相同文件内容可通过摘要识别；去重不能跨凭据或跨服务错误复用。
- 上传记录保存文件标识、大小、MIME、本地源引用、远端 ID、上传时间及到期时间等必要元数据；不把 API Key 写进消息或普通附件记录。
- 服务端到期时间优先于本地推算。过期后再次追问，源文件仍在则重新上传并更新引用；源文件缺失则明确提示。
- 修改服务端点或凭据后，原 ID 不能直接视为可用；根据新配置重新准备。
- 删除一个会话或移除草稿卡片不删除被其他会话共享的云文件。云端文件按上传时设置的期限失效。
- 暂停服务或关闭上传不提前清理云端文件；关闭后的新请求使用旧发送路径，不能遗留不可解析的远端 ID。

## 6. 实现边界与验证前提

| 层次 | 责任 |
| --- | --- |
| 模型目录领域／数据 | 上传偏好、有效期、服务能力与安全配置持久化 |
| 会话领域／数据 | 附件引用、逐文件状态、上传记录、跨会话复用及过期恢复 |
| Agent 数据层 | SDK 上传调用、Chat Completions 文件引用转换、历史重放、流式回复与工具调用兼容 |
| 设置／聊天界面 | 不可变 UI 状态、逐项操作、选择器、图片预览与状态卡；不直接调用 SDK |

已有实现不能直接当作已支持文件上传：当前模型执行边界把本地附件解析为内联内容，现有 ADK OpenAI 适配器对 PDF 等非图片输入有限制。因此需同时实现上传和请求转换，而不是只新增一个上传开关。

当前已从本地 SDK 类型确认存在 `expires_after` 和聊天文件引用字段，但尚未通过官方服务验证完整链路。接入前必须核验：

- Chat Completions 对各格式、图片、模型及文件用途的实际引用支持；不能直接复用 Responses 的输入结构。
- 官方 SDK 与服务端对上传用途、自动过期、期限选项、格式及大小限制的支持。
- 文件失效／删除的错误码与重新上传条件；不能对所有 4xx 无限制重试。

第一阶段进展见 [OpenAI 文件上传与 Chat Completions 验证报告](openai-files-phase1-validation.md)：10 项 SDK 本地 HTTP 验证与 3 项现有 ADK 边界测试通过，官方服务实测因凭据和网络前提缺失而受阻。当前不能将任何格式标记为已通过 OpenAI 官方读取实测。

用户随后选择临时使用 DeepSeek，进展见 [DeepSeek 文件能力核验](deepseek-files-phase1-validation.md)。已找到官方 Messages Files 实现，但 Chat Completions 文件读取仍待真实验证；不得据此自动切换协议。现有设计稿中的 OpenAI 名称为服务示例，逐文件交互结构不因验证厂商调整而改变。

若某格式仅能上传而不能被当前聊天接口读取，应保持协议不变并明确提示不支持，不擅自切换协议。原型中的示例文件、期限、图片与进度均为模拟数据，不能作为 API 能力证明。

## 8. 验收清单

- [ ] 设置：默认关闭；开关与厂商工具独立；有效期默认 7 天；设置保存和放弃行为正确。
- [ ] 选择器：同抽屉切换、服务隔离、搜索多选、返回不提交、添加不立即发送、重复引用去重。
- [x] 默认附件文件卡：每个文件独立；图片有可点击缩略图；所有卡片位于文本输入框外。
- [ ] 部分失败：一个成功一个失败；重试／取消只影响目标文件；已就绪文件不重传。
- [ ] 发送：附件未全部就绪不请求模型；自动继续原发送快照；不覆盖或发送新草稿。
- [ ] 复用：跨会话使用、有效期变化、到期重传、本地缺失、服务端点／凭据变化均有明确处理。
- [ ] SDK：验证实际上传参数和文件引用请求体；验证流式回复、工具调用、历史重放及取消。
- [ ] 回归：关闭上传后旧发送链路保持可用；普通聊天失败布局统一且不重复提示。
- [ ] 视觉：深浅色、长文件名、多附件滚动、键盘及系统安全区域、可访问性均检查。

## 10. 默认聊天界面接入进展

用户选择跳过当前在线实测问题后，先实现与厂商无关的界面基础：

- 默认图片、文档和音频附件各自一张卡，显示名称、类型、大小与实际待发送／准备状态。
- 文件列表在文本输入框外独立滚动；图片复用原有草稿图片解码器，点击沿用现有大图预览；移除仍清理对应草稿副本。
- 普通请求失败的错误及重试移至输入框外状态卡，重试中可取消；原聊天列表中的重复当前错误仅在展示副本中移除。
- 历史错误、已有部分正文和原始消息记录均保留；隐藏交互轮次的错误也按当前轮处理。
- 生成和重试期间可继续编辑新草稿；发送仍受原运行状态保护，重试不带入新草稿。
- 保留必要的历史内容保护回归测试，不加入自动化 UI 交互或截图断言。

生产组件截图位于 `temp/chat-attachments-design/production-images/`；定向测试摘要与渲染复现说明位于该目录的上级目录。该阶段只覆盖默认附件和请求状态；后续上传基础层与云文件入口的实际进展见第 11、12 节。逐文件云端进度仍为原型，不作为已完成能力。


## 11. 云文件基础层接入进展（2026-10-22）

本轮完成数据与领域层的下一步，不改变已确认的界面，也不把本地验证算作厂商实测。

### 已实现

- 服务配置新增独立的上传偏好，默认关闭；有效期默认 7 天，只接受 1 / 7 / 30 天。与连接和模型选择一起加密提交，磁盘写入失败不发布新配置。暂停与恢复保留偏好，删除服务重置偏好。
- 共享文件记录归属会话能力，不绑定单一会话；加密保存文件 ID、来源路径、内容摘要和有效期，不保存 API 密钥。当前服务、协议、地址、凭据摘要共同限定可见和复用范围。
- 本地文件按内容摘要去重；同一连接的并发准备不会重复创建远端文件。重试失败文件保留其他就绪记录，取消向上传播，不发布虚假成功。
- 有效云文件可在本地来源已移除时复用；过期后只有原本地来源仍存在且内容一致才可重传。新有效期不追溯修改旧记录；服务返回更短有效期时采用更短期限。服务未返回到期时间时，只记录本地复用截止时间，不声称远端删除。
- OpenAI Files 使用官方 Java SDK 4.41.0，上传保留原文件名，设置 `purpose=user_data` 和 `expires_after`。关闭 SDK HTTP 状态重试；该 SDK 的 OkHttp 传输已关闭连接重试，避免隐式重复上传。
- DeepSeek Files 根据已归档官方 harness 契约单独适配 `/anthropic/v1/files`、认证头和有效期字段。该适配只负责上传，并不切换聊天到 Messages，也不将该接口冒充 OpenAI Files 兼容接口。其他厂商默认不推定兼容。
- 上传和聊天引用分为两个独立能力。领域准备入口在上传前检查当前服务、模型、文件类型的引用能力；当前生产能力判定仍为未验证，因此不会触发上传或静默回退原发送方式。

### 仍未开放的功能

正式文件引用发送仍未开放。上传开关、云文件抽屉及逐文件发送准备已在后续阶段接入，见第 12、13 节。默认协议保持 Chat Completions；生产能力校验目前会阻止未验证上传。

### 下一阶段验收

1. 实测确认具体服务、模型、文件格式的“上传 → Chat Completions 引用 → 正确读取内容”闭环，分别记录成功和拒绝范围。DeepSeek Messages 引用成功不能作为 Chat Completions 支持证据。
2. 补上 Chat Completions 文件 ID 转换、历史引用恢复与模型边界的作用域／有效期校验，通过实测后按服务、模型、格式开放能力。
3. 验证全部必要文件就绪后才调用模型；取消或失败文件不会被静默忽略；旧请求重试与新草稿隔离。

已知边界：远端接受上传后若响应丢失、用户取消或本地写入失败，客户端可能拿不到可持久化的文件 ID；因此不能保证该窗口下再次手动重试绝不产生重复远端文件，也不能宣称已删除远端文件。已有已持久化就绪记录的重试仍会复用。

## 13. 逐文件准备、重试与取消接入（2026-10-22）

### 实际接入的发送准备流程

- 点击发送后固定原文字和附件快照，每个文件独立归档、上传／复用及发布状态。失败文件保留其它就绪结果，单文件重试复用自己的归档副本，不重传已就绪文件。
- 云上传使用共享工作区中的副本，不移动或消耗原草稿；失败或整体取消不清理原草稿。归档临时副本按取消／失败收尾删除。只有发送被接管后，才沿用原逻辑清理该次提交的草稿。
- 单文件取消标记该文件取消，整次发送继续等待重试，不自动省略附件。整体停止取消整个准备批次，不创建模型执行、不写入半份用户消息。
- 全部必要文件就绪后，按原顺序交给既有发送准备流程，避免二次归档。接管回执仍只消费原快照，后来输入的新文字和新附件保留。
- 在全部就绪时再次检查期限；等待其它附件期间已经过期的文件会独立重新准备，其它有效就绪项不回退。
- 批次身份和逐文件任务身份共同屏蔽迟到结果与旧卡片操作。模型／格式能力在本地归档和上传副作用之前检查，关闭上传的远端引用不能退回本地读取。

### 真实状态卡

原有逐文件卡现在接受真实准备状态：等待、准备中、上传中、就绪、失败和取消。图片仍在自己的卡中显示原缩略图；失败文案使用本地化枚举，提供该文件的重试和取消。SDK 没有字节级回调时使用不定进度，不生成百分比。

原请求的文件卡与新草稿分开显示；正在准备的原请求不因编辑新草稿而变化。未验证引用会在对应卡中显示原因，结束准备并保留原草稿，避免请求级错误卡与文件错误卡重复。

本轮分检查点通过 116 个不同的定向／回归测试，其中包含聊天 ViewModel 现有 69 个行为用例，以及新增的等待、逐文件重试、取消、来源副本保护、等待期间过期和原快照消费边界。模型调用使用模拟执行端；这些测试不作为真实服务支持证据。状态卡另有 12 张实际 Compose 浅色／深色渲染，位于 `temp/cloud-batch-ui/images/`，使用示例数据且没有自动化截图断言。

## 14. 本地原文件优先与云端恢复（2026-10-22）

### 已确认的读取策略

- 上传成功后继续保留应用共享工作区中的原文件，日常显示、预览和跨会话复用优先读取本地文件，不主动删除归档文件。发送接管后仍可清理输入栏的临时草稿副本，不删除共享原文件，也不操作用户相册或下载目录中的来源文件。
- 云上传的图片归档保留原始字节、文件名和 MIME，不沿用默认内联发送的 JPEG 压缩流程；关闭云上传时默认附件处理保持原样。
- 本地来源缺失、损坏或内容不匹配时，才尝试从该文件所属连接下载完整源文件。文件 ID、协议、地址和凭据作用域严格匹配，不使用当前另一服务的凭据下载历史附件。
- 下载到临时文件后校验完整大小和上传时的 SHA-256，成功归档并持久化新的本地路径后才交给界面。取消、截断、内容不一致和存储失败不能发布半文件，并清理该次下载临时产物。
- 缩略图和大图读取同一份本地原文件，仅按显示尺寸解码；点击大图不再次请求另一个原图地址，不新增独立缩略图文件。重新进入聊天或重新加载云文件列表时重新检查来源，允许本地文件被清理后再次恢复。
- 同一连接下并发读取合并复用；下载完成后其它会话也复用持久化的共享路径。图片列表只在图片行进入可见区域后请求恢复，不在打开云文件列表时批量下载所有文件。
- 本地原文件完整时，即使云记录已经过期仍可用于展示。远端过期、本地缺失或厂商无法下载时展示既有不可用占位，不以缺失的预览推断模型文件引用仍然有效，也不静默重新上传。

### 接入范围与边界

- OpenAI 通过已有官方 Java SDK 的 Files Content 接口下载原始内容；认证在数据层处理，不把 API 密钥放入图片 URL，不把鉴权 URL 持久化。下载失败不自动重试；用户重新进入或重新加载才重新尝试。
- DeepSeek 已归档的官方 harness 文件契约只确认上传、列表、元数据和删除，未确认内容下载接口。因此当前保留并展示已有本地来源；来源缺失时不猜测下载端点。其它厂商也不由“兼容 Chat Completions”推定支持文件下载。
- 预览读取与“上传开关”“模型引用支持”分离；已有记录可以恢复预览，不因此开放模型文件 ID 发送。当前生产的文件引用能力守卫仍保持未验证。
- 云文件抽屉、带云引用的草稿和已具有结构化云引用的内存消息使用这一读取路径。**ADK 历史云引用的写入／还原仍属于后续聊天适配工作**；此阶段没有把纯本地历史路径伪装成云文件记录。
- 厂商真实下载权限、具体 purpose 限制和文件类型范围尚未在线验证；本地 MockWebServer 只验证 SDK 请求映射、原字节传输、错误与取消处理，不作为线上支持证据。

### 本阶段验证

本阶段分检查点通过 115 个不同的定向／回归 JVM 用例（领域 10、数据 29、聊天功能 76），70 个模块架构检查及 Debug APK 打包通过。保留下载认证、作用域隔离、完整性校验、取消清理及迟到结果的必要风险边界测试；未增加 UI 自动化测试。日志与结果清单位于 `temp/cloud-local-restoration/`。没有进行设备验证或真实厂商 API 调用，默认 Chat Completions 协议和未验证引用守卫保持不变。

## 15. 默认 OpenAI 协议文件引用适配（2026-10-22）

### 最新能力规则

- 已替换始终返回 false 的 `UnverifiedCloudFileChatSupport`。当前实现为 `OpenAiCompatibleCloudFileChatSupport`：只按 OpenAI Chat Completions 协议及 PDF 输入格式判断，不要求已知厂商、已知模型 ID、官方端点或本地实测登记。能力默认为可尝试，不等于声称所有厂商均已验证成功。
- 文件上传偏好仍默认关闭；所有使用该协议的服务均可配置。打开后本阶段仅选择、上传和引用 PDF，单次文件总量最多 50 MiB。图片、音频和其它文档仍通过关闭上传偏好后的原路径发送；不把上传图片 ID 冒充受支持的 PDF 文件输入。
- 普通兼容服务默认通过官方 OpenAI SDK 调用 `/files`，沿用 `purpose=user_data` 与有效期参数；厂商不支持这些参数或文件引用时显示真实失败，不丢弃附件、不回退内联、不改用 Responses。已有 DeepSeek Files 上传方言继续单独保留，但其返回 ID 能否用于 Chat Completions 不再由客户端未验证白名单阻止，而由服务实际响应决定。

### 请求与持久化

- 云文件使用结构化应用引用编码到 ADK `FileData.fileUri`，包含文件 ID、连接摘要、原附件 ID、大小和可选本地路径；不保存原文件字节、API 密钥或临时下载 URL。历史还原与实时事件映射共用领域编解码器，未知版本／损坏引用不能被当作本地文件读入。
- 每次模型调用，包括工具续轮、重试和整段历史重放，都检查当前连接是否仍启用、上传是否允许、协议／地址／凭据是否仍与模型运行快照一致，并按记录校验作用域、MIME、大小和总量。已过期文件沿用现有共享来源重新准备和内容去重，刷新后的 ID 仅替换本次请求副本；历史保存的应用引用仍可在下一轮解析。
- 含云文件的请求通过独立 `Model` 适配器调用官方 OpenAI Java SDK 的 Chat Completions，发送 `content: [{type: "file", file: {file_id: "…"}}]`。应用内部 URI 和本地路径不进入厂商请求。
- 该适配器保留系统指令、文字／图片历史、函数定义、工具调用与结果配对、严格 JSON Schema、流式文本、工具参数片段聚合、Token 用量和结束原因。没有云引用的请求继续使用既有 ADK 后端。
- 请求／响应转换及流状态基于 ADK 1.2.0 的 Apache-2.0 源码，在 `data/agent/model/files/` 独立包内扩展；保留原版权和许可证头，不访问或伪造 ADK internal 包。SDK 通过其公开的 `HttpClient` 接口接入可取消传输，避免关闭流时等待阻塞读；停止时先取消底层 Call，再关闭流。连接重试和 SDK 自动重试均关闭。
- 请求拒绝保留 HTTP 状态码，不把 SDK 携带的请求／响应原文或异常 cause 直接传给界面。服务拒绝文件读取会使本轮失败，保留原消息供重试。

### 验证边界

真实厂商闭环仍未执行，已有 OpenAI／DeepSeek 实测报告中的网络与凭据限制不变。该事实不再作为协议能力返回 false 的依据。当前以本地 MockWebServer 验证真实 SDK 发出的协议请求，不将本地模拟成功称为厂商实测成功。
